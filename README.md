# 🧠 HOW I THINK ABOUT SOFTWARE

I believe software development is more than writing functions and connecting APIs.

A good product starts with understanding **why it needs to exist**.

My approach:

```text
01  PROBLEM
    │
    ▼
02  RESEARCH
    │
    ▼
03  PRODUCT IDEA
    │
    ▼
04  USER EXPERIENCE
    │
    ▼
05  TECHNICAL ARCHITECTURE
    │
    ▼
06  DEVELOPMENT
    │
    ▼
07  INTEGRATIONS
    │
    ▼
08  TESTING
    │
    ▼
09  DEPLOYMENT
    │
    ▼
10  FEEDBACK
    │
    ▼
11  ITERATION
    │
    └──────────────► REPEAT
```

### My principles

* **Build for people, not just for technology.**
* **Keep complex systems simple for users.**
* **Choose technology based on the problem.**
* **Don't over-engineer unnecessarily.**
* **Ship, learn and improve.**
* **Keep learning new technologies.**
* **Think about the product, not only the code.**

# 🧠 DEVELOPMENT PHILOSOPHY

### 01 — Understand the problem

```text
Don't start with:
"What framework should I use?"

Start with:
"What problem are we solving?"
```

### 02 — Build the simplest useful version

Start with the core experience.

Then improve it.

### 03 — Technology should serve the product

I don't believe in choosing technology simply because it is popular.

The technology should make sense for:

* The product
* The users
* The scale
* The team
* The budget
* The future requirements
